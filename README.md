# Markazi — سيستم توزيع الطلاب على المراكز (إصدار 4.0)

ويب أبليكيشن محلي (Python + Flask) بيوزّع عشرات الآلاف من الطلاب على جروبات مراكز التدريب حسب المحافظة والمنطقة والليفيل/التراك والمسافة بالطريق، مع تحديد مواقع الطلاب من عناوينهم من غير إنترنت، وقاعدة مواقع للمراكز بالتصحيحات اليدوية، وخرايط للمراجعة، ومقارنة بين التشغيلات.

## التشغيل
1. (مرة واحدة) حط `gazetteer.sqlite` في `data\` (شوف `tools/README.md` لبنائها)، ولو عايز مسافات الطرق الفعلية جهّز OSRM (قسم "OSRM" تحت).
2. دوس دوبل كليك على `run.bat` (بيعمل venv ويسطّب المكتبات أول مرة، وبعدين يفتح المتصفح). أو:
   ```
   py -3.12 -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   .venv\Scripts\python run.py
   ```
3. أول مرة: صفحة إنشاء حساب الأدمن (اسم مستخدم وكلمة سر). بعدها تسجيل دخول عادي.
4. **تشغيل جديد** ← ارفع شيت الطلاب وشيت المراكز ← راجع الفحص المسبق ← ابدأ التوزيع.

السيستم بيشتغل على `http://127.0.0.1:5000` (جهازك بس). لو عايز تفتحه على الشبكة المحلية اضبط `SD_HOST=0.0.0.0` في ملف `.env` (انسخ `.env.example`).

## قواعد التوزيع (ثابتة)
1. المحافظة إلزامية: الطالب ما يتوزعش خارج محافظته (`GOV_ALLOW` في `distributor/core/engine.py` فاضي).
2. نفس المنطقة أولًا، وبعدها الأقرب مسافة بالطريق.
3. نفس الليفيل والتراك بالظبط (L3 غير L3WB). اختصارات التراك: CY, DT, WB, DA, EM.
4. أقصى مسافة 50 كم بالطريق (قابلة للتغيير). لو أقرب مركز أبعد: VP مع المسافة واسم أقرب مركز. المراكز الممتلئة ⇒ VP.
5. طالب واحد في جروب واحد. كل تشغيل بيبدأ من الشيت المرفوع (مفيش تثبيت لتوزيع سابق).

## شكل الشيتات
**الطلاب (الشكل القياسي):** `Student NID`، `gov` (بالعربي)، `Area`، `Adress`، `Level(25-26)` (مثل `Level (3): Web`)، و`Latitude`/`Longitude` اختياريين.
**الطلاب (تصدير قاعدة البيانات «Student DB»):** `national_id`، `city`، `area`، `address`، `level`، `group` — بيتقرا لوحده: `city` ← المحافظة، والليفيل من كود الجروب القديم (`ON-CA-L3WB-G1659` ← L3WB)، وكود الجروب القديم بيتحفظ في عمود `old_group`. الأسماء والتليفونات ما بتدخلش النتيجة.
**المراكز:** `Group Code` (مثل `L1_0001` / `L3WB_0003`)، `Center Code`، `Area`، `City` (بالإنجليزي: cairo, alexandria...)، `Day`، `Time`، `Center Name`، `سعة القاعة`، و`Latitude`/`Longitude` اختياريين، وعمود لينك Google وعمود العنوان التفصيلي (اختياريين). إحداثيات المركز ممكن تكون قدام أول روم بس.
- الرقم القومي لازم يتحفظ Text (لو اتحول لـ3.10033E+13 في CSV الفحص المسبق هيمنعك).
- في النتيجة عمود `row_no` = رقم الصف في الملف المرفوع.

## مصادر المواقع
**المراكز:** الموقع بيتحفظ مرة واحدة في قاعدة المواقع. ترتيب المصادر لو الشيت مالوش إحداثيات: القاعدة ← لينك Google (دبوس المكان) ← العنوان (دقة تقريبية، بيتعلّم "راجعه"). التصحيح اليدوي بيتغلب على الشيت دايمًا. مركز موقعه بعيد أكتر من 15 كم عن موقع عنوانه بيطلع تنبيه أحمر (تعليم بس).
**الطلاب:** تصحيح يدوي بالرقم القومي ← إحداثيات الشيت (في الوضع التلقائي) ← كاش العناوين ← قاعدة الأماكن المحلية ← تصحيح مجموعة. كل طالب في النتيجة ليه `geo_source` و`geo_level` (poi / street / locality / area / markaz / gov) و`geo_conf`.
**الدقة المقاسة** (شيت 43 ألف طالب): شارع/معلم ~30%، حي/قرية ~22%، منطقة ~43% (2–5 كم). الطلاب اللي من غير منطقة ولا عنوان موقعهم على مستوى المحافظة. وضع «من العناوين دايمًا» هو الموصى به لأن إحداثيات الشيتات القديمة طلعت مولّدة (الفحص المسبق بيكتشف ده).

## المسافة
- **OSRM** (موصى به): مسافة طرق فعلية من سيرفر OSRM محلي. الكاش في `data/osrm_cache.pkl` بيخلي التشغيلات الجاية ثواني؛ بيتمسح لوحده لو الخريطة اتغيرت.
- **تقدير:** خط مستقيم × 1.3 (قياسنا: ×1.26 عند 50 كم، ×1.4 لـ10–25 كم، ×1.65 تحت 10 كم).

## OSRM على جهازك (بدون Docker)
`tools/osrm/start_osrm.bat` بيشغّل السيرفر على `127.0.0.1:5001` من `%USERPROFILE%\osrm` (أو المتغير `OSRM_HOME`)، و`stop_osrm.bat` بيوقفه. محتاج حوالي 2 جيجا رام.
التجهيز (مرة واحدة):
1. أدوات OSRM لويندوز: `https://github.com/Project-OSRM/osrm-backend/releases/download/v26.10.0/node_osrm-v26.10.0-8-win32-x64-Release.tar.gz` ← فكّها في `bin\` (`bin\binding_napi_v8\osrm-extract.exe` ...).
2. `profiles\car.lua` + `profiles\lib\*.lua` من نفس المستودع إصدار v26.10.0.
3. خريطة مصر: `https://download.geofabrik.de/africa/egypt-latest.osm.pbf` في `data\egypt.osm.pbf`.
4. لو الأدوات وقعت بكود `0xC0000005`: انسخ `msvcp140.dll`/`vcruntime140.dll`/`vcruntime140_1.dll` (14.40+) جنبها أو حدّث VC++ Redistributable.
5. ```
   bin\binding_napi_v8\osrm-extract.exe data\egypt.osm.pbf -p profiles\car.lua -t 4
   bin\binding_napi_v8\osrm-partition.exe data\egypt.osrm -t 4
   bin\binding_napi_v8\osrm-customize.exe data\egypt.osrm -t 4
   ```
   (extract ~5 دقايق، partition ~3، customize ممكن ساعة). الناتج ~2.7 جيجا.
لا تستخدم سيرفر OSRM العام ببيانات الطلاب.

## Google Geocoding API (اختياري، لمواقع المراكز)
لو حطيت مفتاح في `data\google_key.txt` (سطر واحد) أو `GOOGLE_API_KEY`، زر «تحقق بـ Google API» بيفحص المراكز (طلبين لكل مركز: الاسم+المنطقة، والعنوان). بيتبعت اسم المركز وعنوانه بس. التغيير التلقائي بس لو جوجل دقيق ومطابق (≤300 م) للموقع الحالي (يتعلّم «متأكد») أو للينك (يتحرك للينك)؛ غير كده بيتسجل للمراجعة. عداد شهري وحد أقصى 9,000 طلب (المجاني 10,000). المفتاح عمره ما بيتحفظ في الـDB ولا بيظهر في الصفحة. راجع شروط جوجل لتخزين النتايج قبل الاستخدام الدائم. مفيش الميزة دي للطلاب.

## الأمان والخصوصية
- دخول إجباري، كلمات سر مشفّرة، سجل تعديلات (`audit`) لكل تصحيح يدوي.
- السيرفر بيرفض الطلبات اللي جاية من صفحات مواقع تانية (Origin) ومن أسماء Host غير محلية.
- كل الملفات اللي فيها أرقام قومية في `data/` ومستثناة من Git (`.gitignore`). الشيتات التجريبية في `sample/` وهمية بالكامل.

## هيكل الكود
```
run.py / run.bat            تشغيل
distributor/
  config.py                 المسارات والإعدادات (.env)
  __init__.py               create_app + حارس الطلبات + تسجيل الدخول
  auth.py  db.py  jobs.py   المستخدمين / جداول التطبيق / مهام الخلفية
  core/                     engine (التوزيع) · geoprep (تجهيز المواقع) · geocoder+geonorm (العناوين) · locdb (قاعدة المواقع) · googlegeo
  services/                 sheets (قراءة الشيتات) · preflight · runs · compare · whatif · exports · centers
  web/                      pages (HTML) · api (JSON) · templates/ · static/
tools/                      بناء قاعدة الأماكن، OSRM، توليد عيّنة
tests/                      pytest (python -m pytest)
```
النتيجة لنفس المدخلات ونفس التصحيحات ثابتة دايمًا (مفيش عشوائية)، والمحرك هو نفسه اللي اتحقق منه في الإصدارات السابقة طالب بطالب.

## الرفع على GitHub
الفولدر جاهز كـrepo (ملف `.gitignore` بيستبعد `data/` وكل الشيتات والقواعد والمفاتيح). من **GitHub Desktop**: File ← Add local repository ← اختار الفولدر ← Publish repository (خلّيه **Private** لأن المشروع بتاع بيانات طلاب). أو من سطر الأوامر:
```
git init
git add .
git commit -m "v4.0.0 web application"
git branch -M main
git remote add origin https://github.com/mahmoudabdelmoneem960/Markazi.git
git push -u origin main
```
قبل أي push اتأكد إن `git status` مش بيعرض أي ملف من `data/` ولا أي شيت حقيقي.
